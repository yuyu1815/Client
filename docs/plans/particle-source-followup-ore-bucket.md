- `world/level/block/RedStoneOreBlock.java`
  - `attack` calls `interact` (both sides); `stepOn` calls `interact` unless `Entity.isSteppingCarefully()`; `useItemOn` spawns particles client-side and calls server-side `interact`, then returns `PASS` only for a `BlockItem` whose `BlockPlaceContext.canPlace()` is true, otherwise `SUCCESS`.

- `world/item/BucketItem.java:55-100,120-157`

  - `emptyContents(pos, hitResult)` tries its supplied position; on failure it recursively tries `hitResult.blockPos.relative(hitResult.direction)` with a null hit result. Thus the audit concern conflated the clicked `hitResult` position with `emptyContents`' supplied candidate: the Rust adjacent choice was correct for replaceable non-container clicks.
  - A candidate succeeds when air, or replaceable/container and not shift-blocked; failed solid candidates produce no evaporation smoke. `WATER_EVAPORATES` is evaluated at the final candidate. Block interactions that consume the click do not fall through to `BucketItem.use`.
- `core/cauldron/CauldronInteractions.java:58-60,113-120,148-150`: water bucket is registered as a successful `useItemOn` interaction for empty, water, lava, and powder-snow cauldrons. The Rust WaterBucket path now consumes those clicks before testing evaporation; sneaking bypasses the block action just like Java.

## Rust ownership / changes

- `world/particle_tick.rs::redstone_ore_interaction_requests` is the shared visible-face Dust request generator. `player/interaction.rs::start_attack` and the RedStoneOre block-input branch in `InteractionState::start_use_item` are action sources. The local player uses `local_block_effect_particle_requests` after physics in `app/phases/in_game.rs`; the same eligibility gate feeds PowderSnow and Ore. `entity/particle_tick.rs::tick_living` now emits contact Ore only for the local player or a living mount whose Java controlling passenger is the local first-seat Player, and only when grounded/not carefully stepping. Horse-family/Camel/Nautilus require saddle; Pig and Strider also require their respective held steering item. Remote living players/mobs do not emit. Grounded generic vehicle entities use their movement packet bit and Java `applyEffectsFromBlocks` caller eligibility; Arrow/SpectralArrow/Trident use metadata ID_FLAGS bit 0x02 for noPhysics, shared flag 0x04 is unrelated, and ShulkerBullet keeps its fixed noPhysics suppression. Grounded item entities are queried by their owning `ItemEntityStore` after its tick. Regular lit ore animate sampling remains separate.
- `world/block/mod.rs::can_place_water` and `can_be_replaced_by_water` carry state-level water placement decisions; the latter mirrors the vanilla default `replaceable || !legacySolid` using the native collision shape, with the two source-confirmed `EndPortalBlock`/`EndGatewayBlock` fluid-overload overrides. The interaction destination query models clicked-container vs adjacent selection, sneaking fallback, unloaded-candidate rejection, and null-hit recursive fallback. `core.rs` evaluates biome/dimension/timeline water evaporation at this candidate.
- A replaceable non-container click still selects adjacent position. A solid adjacent candidate returns no destination; it cannot produce 8 smoke particles. The item-use branch is only reached if prior block interaction passes. RedStoneOre consumes non-BlockItems unless sneaking bypasses block use; valid placeable BlockItems pass through to block placement.
