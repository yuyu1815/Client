# Java 26.2 miscellaneous nonliving/projectile particle sources

Implementation owner: `pomme-client/src/entity/particle_misc.rs` (`State`, `on_spawn`, `on_metadata`, `on_event`, `tick`). State is owned per entity id in `EntityStore::misc_particle_state`; it is created from the nonliving type, removed by `EntityStore::remove_entity`, and reads position/velocity from existing `VehicleState`. Ender Pearl collision tracing and boat bubble-column contact are performed inside this tick helper; no separate collision/event trigger is required once the parent appends its returned requests. This is visual-source state, not fabricated living AI.

## API / missing integration

- Spawn hook: `EntityStore::misc_particle_on_spawn(id, kind)`; append its result once in `app/core.rs` `NetworkEvent::EntitySpawned` arm after nonliving registration, especially for LlamaSpit. `set_vehicle_spawn_data` copies nonzero AddEntity owner data into pearl misc state (0 remains `None`), but the current `EntitySpawned` match at `app/core.rs:5258` omits `spawn_data`; the live nonliving path must forward it via `register_nonliving_spawn_event` before owner filtering is effective.
- Metadata hook: `EntityStore::misc_particle_metadata(id, index, MetaValue)` after native-version translation, adjacent to `apply_vehicle_metadata` in `app/core.rs` near line 5778. Route cloud kind/options (metadata 10) through `misc_particle_cloud_options`; metadata 8 radius and 9 waiting use scalar metadata. Existing `apply_vehicle_metadata` does not automatically call it.
- Ender Pearl impact requires no separate event or RemoveEntity hook: `misc_particle_requests(chunks, game_time, spectator_uuids, local_player)` traces the next movement segment each fixed tick and only emits for a confirmed hit. The live caller supplies both inputs.
- Event hook: `EntityStore::misc_particle_event(id, event)`; forward raw EvokerFangs event 4 and MinecartTNT event 70. Current `NetworkEvent::GolemPunch` arm in `app/core.rs` near line 5876 is the typed event-4 route (must still call misc hook); handler needs a raw event-70 route because `MinecartTNT.handleEntityEvent(70)` primes its local fuse. Fangs starts countdown without immediate output; minecart event starts its 80-tick smoke clock.
- Tick hook: `app/phases/in_game.rs` calls `EntityStore::client_particle_requests(&game.chunk_store, &spectator_uuids, Some(local_player_view))` once per fixed client tick; immediately before that it sets game time from `game.sky_state.game_time`. `spectator_uuids` comes from `game.tab_list.players` (`game_mode == 3`); `local_player_view` is `LocalPlayerProjectileView { entity_id: game.player.entity_id, bounds: game.player.bounding_box(), is_spectator: game.player.game_mode == 3, is_alive: game.player.health > 0.0 }`. This forwards explicit inputs into `EntityStore::misc_particle_requests(chunks, game_time, spectator_uuids, local_player)` for the pearl/boat query; no frame-rate caller or implicit `None` production wrapper.
- Existing `EntityStore::client_particle_requests` has no game-time parameter; keep this separate for the parent aggregator to provide actual `game_time`.
- AreaEffectCloud particle option cannot be expressed by scalar `MetaValue`; the dedicated `EntityStore::misc_particle_cloud_options(id, kind, options)` accepts the already-translated exact particle kind/options. Wire the protocol particle-metadata branch there. `wait_time`/duration are not encoded by a live synced timer; the server's waiting boolean is the correct client condition.
- Java `MinecartTNT.handleEntityEvent` uses event 70 and `primeFuse` sets client fuse to 80. Event 10 belongs to unrelated entity semantics and is not used.
- Java `BubbleColumnBlock.entityInside` is gated by `isPrecise`, invokes per intersected block cell, and distinguishes `onAboveBubbleColumn` from `onInsideBubbleColumn` using above-cell collision/fluid state. Boat splash and its local sound share one 1/100 callback gate; bubble-column block `animateTick` ambience is a separate existing particle owner.
- Projectile block collision uses `player::interaction::raycast_collision`, a separate COLLIDER mode over the shared block-ray traversal; the player selection `raycast` remains outline-based. Fluids are not clipped. CollisionContext receives the pearl's bbox bottom and non-descending state, including position-dependent scaffolding/moving-piston shapes and Powder Snow's empty projectile collision. Entity margin follows Java `ProjectileUtil.computeMargin` (clamp((tickCount - 2) / 20, 0, .3)). Owner/root, tracked spectator UUIDs, and the explicit local-player id/bbox/spectator/alive view feed entity filtering. `Projectile.hitTargetOrDeflectSelf` returns early on non-NONE `Entity.deflection`; a Breeze hit therefore classifies the segment as `Deflected` and cannot fall through to a wall. Owner ids come from AddEntity `data` in `VehicleState::spawn_data`.
- Arrow flag uses Java `AbstractArrow.ID_FLAGS` metadata index 8, bit 0. The server can clear it at impact; local output occurs only while the synchronized flag remains set.

## Final integration status (2026-10-05 snapshot)

This section supersedes the earlier "API / missing integration" callsite instructions above.

- `EntityStore::client_particle_requests` calls the misc owner once per fixed client tick with current game time, spectator UUIDs, and local-player entity ID/position/bbox height/bounds/alive/spectator fields. Its output reaches the existing `ParticleStore` spawn path.
- `NetworkEvent::EntitySpawned` calls `misc_particle_on_spawn` after living/nonliving registration and enqueues the returned typed requests once. AddEntity `spawn_data` is carried into nonliving registration, so Ender Pearl owner and LlamaSpit spawn behavior use packet data.
- Entity scalar metadata calls `misc_particle_metadata`; entity event dispatch calls `misc_particle_event`. Event 4 calls `handle_particle_mob_event` and still dispatches legacy `GolemPunch`; events 39/69 now reach Ravager phase handling; event 70 starts the TNT Minecart fuse. Fangs event 4 and TNT event 70 are not swallowed.
- Ender Pearl impact and Boat contact run through the aggregate tick. Their bounded tests cover actual segment hit/miss, owner/spectator filtering, water/solid/deflection behavior, bubble-cell contact, and one-shot effects.
- **Still not connected:** AreaEffectCloud custom particle kind/options. `misc_particle_cloud_options` and `particle_misc::set_cloud_particle` remain helper-only: Azalea's typed particle metadata is still routed to effect-particle state rather than decoded into the cloud's exact `ServerParticleKind`/options. Do not claim arbitrary synced cloud particle parity.
- Ominous item-spawner RNG remains a stated approximation. Pearl block query uses the current client ray/collision API; parity for less-common dynamic collision contexts and deflection was not verified against a running Java client.

The final workspace test run exercises the current source snapshot; this evidence does not imply all inventory callsites or visual parity are closed.
