## Rust integration

- `pomme-client/src/world/block_entity.rs`: `MobSpawner` registry variant routing, raw-NBT-derived spawner/vault/conduit target visual state, and block-update creation for the client-ticked sources.
- `pomme-client/src/world/block_entity_particle.rs`: builds ordinary native `ParticleSpawnRequest`s; does not instantiate provider particles or process server events.
- `pomme-client/src/entity/mod.rs` plus the one-line AddEntity call in `app/core.rs`: maintain a UUID→live-entity index without changing existing entity state fields, for lazy conduit target resolution.
- `pomme-client/src/app/phases/in_game.rs`: the fixed client tick passes loaded `ChunkStore`, actual local/remote player UUID/position/height, `EntityStore`, and game time; requests use the existing `ParticleStore::add_particles_from_packet` API. `LevelParticles` is unaffected.
- `app/core.rs`'s `NetworkEvent::BlockEvent { pos, block, action_id, .. }` arm filters the packet kind to `potent_sulfur` before calling `on_potent_sulfur_block_event`; the helper rechecks current block, BE type, and action 0. NoteBlock, bell, pot, and chest handling remains unchanged.

This is a source audit/status ledger for this owned BE slice, not a claim that all Java block-entity particle behavior is complete.
