# Elder Guardian model particle coordinate space

Java 26.2 `ElderGuardianParticleGroup` builds the camera-facing model transform from identity: camera rotation, particle X rotation, signed scale, and model translation. The particle's world spawn position is used for range/lifetime behavior, not model placement. Rust's entity vertex shader (`renderer/shaders/entity.vert`) subtracts `CameraUniform.camera_pos.xyz` from every transformed vertex, so the model instance root must first translate to that same camera position relative to the render anchor.

`Renderer::render_world` now takes `camera_position_relative` from the actual frame `CameraUniform::camera_position()` and passes it to `EntityRenderer::draw`. The Elder Guardian root is `T(camera_position_relative) * Rcamera * Rx * S * Tmodel`; shader subtraction cancels the first translation and leaves the Java camera-relative model. The request's interpolated spawn position remains intact for particle-side range checks but is not used to place the overlay. Existing entity shader, Elder Guardian baked model/part transforms, alpha, rotation, signed scale, model translation, and full-bright draw record remain unchanged.

CPU-side coverage is in `renderer/pipelines/entity_renderer.rs::tests::elder_guardian_particle_maps_camera_matrix_and_real_model_parts_to_draw_records`: nonzero camera/anchor, non-identity rotation, spawn-position invariance, parallel camera+anchor translation, shader camera subtraction, actual Elder Guardian model part ranges/poses, alpha and full-bright record. Age boundary values (0, 15, 30 ticks) remain covered by `particle::emitters` tests. These are CPU matrix/consumer checks only; no GPU or in-game visual comparison was performed.
