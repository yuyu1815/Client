## 対象と責任境界

チャット機能は、入力editor/draft/history/cursor、候補要求と表示、受信messageの意味上の選択・visibility/filter/delay、transcriptとrich text表示/action、narration triggerを所有する。主なPomme状態正本は `Client/pomme-client/src/ui/chat.rs:516-570 ChatState`。公式では入力screenとHUD transcript/queueが `ChatScreen` と `ChatComponent`、遅延・受信判断が `ChatListener` に分かれている。

責任境界は次の通り。

- **chat → connection-and-protocol:** chatは `RawChat` / `Command` のsemantic intent、候補要求及び表示結果（shown/hidden）を渡す。connection-and-protocolはsession/auth/key、署名生成・検証、last-seen/ackのwire状態、packet framing/version変換、transport失敗を所有する。chatは暗号・sessionを実装せず、表示前にack済みと見なさない。受信semantic envelopeには少なくともmessage identity/signature参照、sender/source/chat type、signed/unsigned候補、filter/validation/trust情報を含め、protocol側のprocessed契約を保持する。
- **順序・終端:** 受信はdecode/validation結果→secure/unsigned内容選択→block/permission/visibility/filter判断→必要なdelay→表示または抑止→一度だけprocessed(shown)結果、の順に扱う。遅延中はprocessedを先送りする。削除・切断・抑止は署名参照と対応した終端結果を重複処理しない。署名不正、未解決sender、fully-filtered、hidden/blocked、空表示のshown値は公式ケースごとに照合し、transport ownerと契約する。
- **権限:** `ChatAbilities`の送信/受信制限とローカルvisibility設定は別概念。設定で隠すことをserver権限の代替にせず、権限拒否時は送信しない/制限案内を表示する。メッセージ本文・slash command・click actionで制限を迂回させない。
- **隣接owner:** menusが設定保存とRestrictions/Options遷移、HUDがactionbar及び全overlay重なり順、resourcesが翻訳/font資産の寿命、item-renderingがhover item/entityの資産・tooltip、connection-and-protocolが運搬を所有する。chatはそれらへ必要な表示/入力契約を出すが隣接planの領域を実装しない。server-gameplayはcommand権限・server authorityを所有する。

### 署名、secure snapshot、削除終端の受入条件

- 署名chain/鍵session/last-seen tracker/ack packet wireとsigned command argumentsの暗号・抽出・送信はconnection-and-protocol owner。chat scopeはsemantic eventがidentity/referenceを保持し、UIがprocessed outcomeを渡す契約まで。現行`InboundChat`参照箇所とoutbound signed argument mappingの完全な対応は未確認である。
- `ChatListener.handlePlayerChatMessage` (`ChatListener.java:95-109`) がsecure-only設定を受信handlerで読み、content選択・trust判定をdelay closureへcaptureするのに対し、Pomme `AppCore` (`app/core.rs:4881-4937`) はqueued `NetworkEvent`消費時に設定を読む。比較は同一packetを受信直後に設定変更、event channel待機中に変更、UI delay queue中に変更の3時点で行い、official captureがqueue後に変わらず、Pommeもarrival snapshotを維持することを要件とする。queue後設定変更が過去messageのshown/hiddenを再評価しない。
- 表示済み、visibility Hidden、secure-only抑止、blocked、権限拒否、fully/partially filtered、invalid署名、profile未解決、delay中delete、既表示deleteを別ケースにする。公式caseごとの`markMessageAsProcessed(shown)`またはignore/deleted動作とPomme `ChatMark`結果を対応表に記録し、表示されたmessageだけshown=true、意図的に表示されないmessageは対応するhidden終端、未終端はqueue中だけとする。1 identityへ終端markを重複追加せず、署名参照を別messageに誤適用しない。

## Brigadier command parse / suggestions / UTF-16 契約

現行の`net/commands.rs`はflat Brigadier node list parserで、Unknown parser等を部分的に扱う。`ui/chat.rs`はcaretまでのlocal parse/literal completion/usageとserver completion要求を組み合わせるが、公式`CommandDispatcher`のparser/node/consumer全網羅は未確認。signed argument extractionはconnection-and-protocolの送信署名経路に属し、local parseが同値と推定しない。

- 公式母集合は`ClientboundCommandsPacket`で渡る全NodeType/argument parser/serializer/property、redirect/fork、複数potential branch、requirement predicate/権限制限、command consumer、usage/parse exception contextと、`CommandSuggestions`のserver suggestion/custom completionの全経路。各parser登録・packet decoder・Pomme `BrigadierParser`/`net/commands.rs`実装・consumerの対応表を作る。`Unknown` parserは現状 unknown/partialであり、未登録parserの挙動やserver権限predicateのlocal再現を達成扱いしない。
- Candidate requestはrequest IDだけでなく、送信時入力全文、caret、入力generation、local suggestions/rangeをsnapshotとして対応付ける。応答は現在のIDとsnapshotが一致し、入力/caretも適用条件を満たす場合のみ適用。入力編集・caret移動・tree差替え後の古い応答、重複/未知ID、malformed/out-of-range rangeは無変更で捨てる。現状`ui/chat.rs:1202-1479`はpending IDとrequestを保持しIDを照合するが、入力snapshot/caret/tree generationすべてを関連付ける契約と古いresponseの全ケースは未達候補。
- Local literal suggestionsとserver-provided optionsのmerge、優先順、case/order、同一候補重複、replacement rangeは公式`CommandSuggestions`との比較で決定する。空server応答時のlocal fallback、server optionsがある場合のlocal literal保持/置換、並び順、range endがrequest caretか入力末尾か、error/usage context位置、permissions制限表示を個別に記録する。現在はserver options非空ならlocalを置換し、空ならlocal fallback、suggestion sortingはtyped-prefix優先。互換性は未検証。
- Wire上の`start`/`length`とBrigadier suggestion ranges/cursorはJava UTF-16 code unit。Rust byte offsetまたはeditor表示caretへ直結しない。境界でUTF-16→UTF-8 byte、byte→UTF-16、editor caret/IME preeditの変換を一箇所のcontractとして定義し、非BMP emoji、結合列（code point boundaryでもgrapheme boundaryでない）、中央caret、0/end、負/overflow/範囲外、surrogate pair途中を比較する。surrogate途中/範囲外はPommeの`utf16_offset_to_byte` (`ui/chat.rs:2953-2973`)で拒否される部分は既実装。これは全range/responseの互換証明ではない。start/endのいずれかがsurrogate途中・request外・start>endならresponse全体を適用せず、入力は保持する。送信後に編集された入力には旧responseを絶対適用しない。
- Signed command argument extractionはparserのargument node identity/range/branch、signed/unsigned扱いのpacket intentに結び付ける。redirect/fork・複数branch・権限制限・Unknown parser・signed-required commandを含むparse結果が署名対象にどう反映されるかはprotocol ownerと照合し、local usage successだけで送信可否を決めない。

## 互換にする設計

1. **状態は責務と寿命ごとの唯一ownerへ分ける。** `InputModel`がeditor/cursor/selection/draft/history、`TranscriptModel`がrenderable lines/wrapped rows/scroll/fade/delete presentationを所有し、`ChatDeliveryPolicy`が受信のpermission/visibility/trust/filter決定・delay queue・表示終端(shown/hidden)を所有する。これは1個のChatStateへの機能全集約ではなく、公式 `ChatScreen` (input) / `ChatComponent` (HUD transcript) / `ChatListener` (receive policy, delay, processed decision) の責務境界を保つ提案である。小さなCoordinatorはモデル間遷移を仲介するだけで状態を複製しない。connection adapterがsignature identity/ack transportを所有し、policyには同一eventのprocessed結果を一度だけ返す契約を渡す。Input/TranscriptのUI stateはchat-owned、connection stateはconnection-owned。delay schedulingの唯一時計はpause-aware client gameplay tick/time sourceをpolicyへ注入する。公式 delayed message timing (`ChatListener` `previousMessageTime`/pause-adjusted clock) と transcript delete timing (`ChatComponent` HUD tick, 60 ticks) は異なる規則として保つ。Pommeのwall-clock `Instant`使用 (`ui/chat.rs:771-795,901-935`) は公式pause semanticsと異なる可能性があり要比較.
2. **送信はsemantic intentとして一度だけ確定:** IME/editor→権限検査→公式26.2と同じspace/trim/256 UTF-16規則→空入力処理→history規則→`RawChat`か`Command`へ分岐。command tree parseやsigned argumentが必要な場合はprotocol ownerに渡す。接続拒否/能力拒否/encoding失敗では履歴追加・closeが公式と同じ順序になることを定義し、未送信を送信済み扱いしない。RunCommand/custom actionは通常入力と同じpermission/signed-command policyを迂回しない。
3. **候補応答は要求時入力snapshotに結びつける:** request id、入力generation、UTF-16 start/length、対象text/caretを保持し、最後の一致する要求の応答のみ適用。UTF-16 offsetはRust string境界へ安全に変換し、surrogate/IME preedit/結合文字を分断する無効range・stale responseはfieldを変更せず破棄する。Tab/矢印/候補選択/入力履歴時の公式優先順を保つ。
4. **受信を明示的なsemantic state transitionにする:** protocolが渡す検証済みenvelopeから表示contentを選ぶ。permissions・visibility・blocked/filter/trust/fully-filteredを区別して評価し、playerだけdelay、systemは公式規則どおり即時扱い。公式 `ChatListener.handlePlayerChatMessage` は `:95-109` でpacket handlerに入った時点に `onlyShowSecure` を読み、表示content/decorated valueと`received`を作ってclosureへcaptureし、遅延後にも同じsnapshotを `showMessageToPlayer` (`:154-165`) が使う。Pomme `AppCore` (`Client/pomme-client/src/app/core.rs:4881-4937`) はNetworkEventを処理するとき `game.chat.only_secure()` を読む (`:4891-4895,4924-4930`)。`ChatState::push_message_with_source` (`Client/pomme-client/src/ui/chat.rs:718-730`) でも受信処理時の設定値を参照する。しかしこれはtransport packet arrival時の値と同じとは、decoder→queued event→app consumptionの全経路を追うまでは断定できない。方針は公式同様に**受信handler/enqueue時のimmutable snapshot**を、content選択・trust判定・遅延表示まで同一eventに付随させること。Pommeが実際にその時点を捕捉/伝搬しているかは未確認であり、event queue ingressまで追跡するまでは互換達成扱いしない。表示受理または非表示終端の一方を一度だけ決定し、signature processed(shown)を実際の結果に結び付ける。切断/queue flush/設定変更にも漏れ/二重ackがない.
5. **rich componentを解決値と未解決表現に混同しない:** translation/score/selector/NBT/objectは解決contextの所有者とタイミングを明確にし、到着済みresolved textを勝手に再解釈しない。Component treeのsibling・親style継承、font・glyph・insertion・obfuscation・shadow/decorations、全event variantを保持し、描画失敗/未知variant時のfallbackを明示する。font/lang資産はresources、item/entity tooltip asset renderingはitem-renderingへ照会する。
6. **click actionは信頼境界を持つ:** server-originatedとlocal/trusted componentを出所付きで区別。公式 `ClickEvent.Action` は8種を宣言し、server-safe codecでは `open_file` を拒むが (`ClickEvent.java:38-78`)、generic `Screen` click handlerにはOpenFile経路 (`Screen.java:270-320`) があるため「公式で非対応」とはしない。URL scheme/confirmation、run command permission/sign policy、suggestionへの挿入、clipboard、dialog/custom routingをactionごとに制御する。`ChatScreen.handleComponentClicked` (`ChatScreen.java:211-265`) のgeneric fallbackと `BookViewScreen` のChangePage consumer (`BookViewScreen.java:239-267`) を踏まえ、Pommeの `ChatState`内ChangePage no-op (`Client/pomme-client/src/ui/chat.rs:1641-1701`) を全consumer不在の証拠としない。screen contextがbook page navigationを提供しない場面の正確な公式fallbackと他のChangePage producer/consumer網羅は未確認.
7. **overlay・narration契約:** transcript/actionbarを別semantic channelとし、`system_chat.overlay`/`set_action_bar_text`はHUD ownerへ渡す。chat transcriptのdraw order/scale/opacityとnarration triggerをHUD/menu/preferencesへ契約するが、preferences保存やHUD全体の順序をchatが所有しない。
