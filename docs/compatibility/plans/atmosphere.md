## 対象と責任境界

この機能は**描画consumer**であり、共有world stateやserver authorityを所有しない。dimension type、解決済みbiome/environment attributes、時刻・天候、カメラ位置のfluid/block、player status effects・boss fog signal、補間済みborder geometryを入力に、視覚状態を作る。packet decode/registry同期はconnection-and-protocol、各状態のauthority・tick・生成はserver-world/server-gameplay、pack画像とreload generationはresources、terrain mesh/depthとfog shader契約はblock-rendering、降雨particle/audioはparticles/audio、border collisionはphysics、boss signal producerはHUD/ゲーム状態側が所有する。ここではそれらを描画用に読むだけで、入力を書き戻さない。

設計目標は一つの描画snapshot **`AtmosphereFrame`** をpartial tick・camera・dimension identity・resource generationに結び付けて一度抽出し、sky / cloud / weather / terrain fog / borderが同じsnapshotを見ること。frameはimmutableで、fog color、fog mode/range、skybox/celestial、cloud/weather option、border tint/alpha/geometryを別の意味表現として保持する。fogを単一の「勝った環境」や色値に潰さない。更新順は入力補間と属性probe → 優先規則/effect合成 → frame確定 → 描画consumer。dimension切替、teleport、pack reloadで旧補間履歴を破棄し、新generationのresourceを揃える。時刻wrap/逆進時計でも補間時刻を一貫させ、水fog色遷移、border lerpはworld tick基準、描画partial tickは同一frame内でのみ使う。

各環境属性の正本/同期はprotocol・world input側、描画直前の空間サンプル/補間はframe extractor、GPU表現は各render consumerに置く。属性不正・未提供時は26.2 codec/defaultと公式既定値に従い、破損resourceは旧generationを部分混在させず、再load errorを可視化・報告して安全な既定/直前の完全generationへ退避する。具体的な失敗時挙動は公式reload lifecycleとの照合後に確定する。

## 互換にする設計

1. **Frame coherence and ownership.** Gather read-only resolved inputs once for a `(dimension, camera, partialTick, world-time sample, resource-generation)` frame token. Sample spatial attributes using the same probe position/blend radius; consume camera fluid separately from biome-underwater status. Snapshot includes interpolated border bounds and all values needed by atmosphere passes. If required input or matching generation is missing, do not mix current and stale generations; apply the source-defined default/hold policy once specified. On world/dimension replacement, teleport discontinuity, resource reload and renderer recreation, invalidate temporal history and restart interpolation only from a valid new baseline.
2. **Fog as orthogonal products.** First select the first applicable one of six environments in official order for environmental range; independently select first color provider, then compose darkness modifier and special vision/void/darken-world rules; finally apply render-distance range. Carry environmental start/end, cylindrical render-distance start/end, sky end, cloud end, color, darkness and source mode separately through shader uniform contract. Keep fluid mode (NONE camera maps to ATMOSPHERIC) separate from world biome. Preserve official math/constants listed above and operation order; clamp only where 26.2 source/codec does. All world/entity/particle/item/block-entity/water/shadow consumers must agree on fog coordinates, distance shape, alpha/color space and selected frame. Boss overlay changes the official world-fog bounds without changing unrelated water/lava precedence.
3. **Sky/time and transition.** Resolve skybox from dimension type; `NONE` suppresses celestial pass, `END` uses end sky, `OVERWORLD` uses disc/sunrise/celestials. Attribute-provided celestial angles/color/phase/brightness take precedence as specified by official resolved probe; time drives only defaults where 26.2 does so. Handle 24,000-tick phase and negative/reversed/frozen server clocks without stale prior dimension interpolation. Keep fog-color sunrise combination and weather dimming independent from the sky disc clear color.
4. **Cloud/weather.** Consume resolved cloud status, cloud range, cloud height/color/fog-end, rain level and per-column biome precipitation/temperature/light from one frame. OFF draws none; FAST/FANCY each retain their official geometry and occlusion semantics. Cloud scroll uses game time + partial tick with wrap-safe coordinates; range must cover option endpoints rather than fixed-buffer truncation. Weather columns use full configured radius and all RAIN/SNOW/NONE climate outcomes, rain intensity, correct texture phase, light and distance fade; do not turn lightning into precipitation. Resource handles are pinned to one reload generation.
5. **Border.** Visual extraction uses interpolated center/size at frame partial tick, all four sides, status color, official UV/texture, alpha/fade, render-distance visibility and depth target. Do not own/update packet state, warning/collision or border tick; protocol applies decoded updates and physics consumes the shared state. Equal endpoints, immediate resize, growing/shrinking, zero/backwards elapsed time and approaching/behind-camera edges need explicit cases.
6. **Data and configuration.** Keep the 24-key table as the full official visual-attribute inventory. Atmosphere implements/evaluates only its 17 owned keys, including defaults, validation, spatial vs nonspatial interpolation, and dimension then biome/environment override semantics where source-defined. The five lighting keys are block-rendering-owned and the two particle keys are particles-owned: those owners evaluate, hold, and update them; atmosphere receives only a read-only snapshot for any required visual consumption and never re-evaluates or updates them. Treat acceptance of these seven consumer contracts as an atmosphere dependency, not ownership of neighboring implementations. Option defaults/bounds/effect scaling follow official `Options`, accessibility controls remain effective at their corresponding visual consumers. Unknown defaults/schema/reload behavior remain unresolved until sourced; do not invent values.
