## Scope, owners, and world-state model

The finite target to close is the **SteelMC generation/biome/dimension/chunk/save/world-tick/block-fluid-redstone surface**, compared with the **entire official Java 26.2 integrated-server world-side surface** reachable from integrated-server world creation, generation, ticking, and persistence. The official side is a complete call/registration/consumer closure to be enumerated; `ServerLevel` and other examples below are entry points, not the whole denominator. Close inherited methods, registries, dispatchers, helpers, and cross-component handoffs before calling the inventory complete.

State ownership: a validated world snapshot owns seed, dimension/generator selection, fixed resolved data, world clocks/weather and tick queues. A chunk lifecycle owner advances generation/loading status and publishes completed chunk state. Runtime world scheduling owns ordered block/fluid/scheduled/random ticks, block events, neighbor updates, and redstone transitions. Persisted state must reload before a resumed lifecycle proceeds. Generation writes/templates belong here; block-entity gameplay semantics, loot/opening, player authority/combat/items/commands, mob AI and natural-spawn decisions belong to `server-gameplay`. `singleplayer-lifecycle` owns start/save/pause/shutdown orchestration; this plan owns world/chunk snapshot correctness. `connection-and-protocol` transports semantic outputs; `atmosphere` owns presentation, not server weather effects. Cross-tree contracts are handoff items; do not edit other plans/trees here.

## Compatibility design to realize

- One world snapshot defines seed, dimension/generator, fixed data, tags/references and provenance. Missing or invalid required inputs fail with a keyed error; never silently select fallback terrain/data. Runtime datapack JSON is not introduced as a compatibility shortcut.
- Generation progresses only when official-equivalent prerequisite status/region requirements are met. Stage outputs remain unpublished until complete; cancellation/failure cannot expose a partially advanced chunk. Seed/RNG family, salt/draw sequence, iteration order, coordinate rounding/floor rules, density precision and write bounds are explicit compatibility contracts to be established from source.
- Chunk save records status and all state needed to continue without repeating committed stages or losing structure references, biomes, sections, heightmaps, light or pending ticks. Load restores it before resumed processing; malformed data fails without overwriting user data. These are target invariants, not claims about current serializer behavior.
- Runtime phases, clock snapshots, scheduled and random work, block/fluid callbacks, block events, neighbor updates, redstone and weather effects have one explicit world-owned ordering contract derived from the complete official graph. Preserve observable state/event ordering and bounded work semantics; keep incidental algorithm differences separate from user-visible differences.
- Semantic boundaries remain explicit: gameplay decisions and lifecycle orchestration are handoffs, not duplicate owners. Emit stable ordered world outcomes to the existing consumers; do not infer client rendering or packet transport behavior from server state alone.

## Open uncertainties and boundaries

- Official integrated-server full mother set/call graph and exact artifact provenance are not yet recorded; cited classes are entry points only.
- The local source/decompile alone does not establish every runtime-resolved value or dynamic registry. Steel generated/extracted data provenance and consumer joins remain to be traced. The appendixed declaration counts require source/registration revalidation and are not closure claims.
- Exact serializer/deserializer ownership, structure start/reference persistence, status resume behavior and pending-tick save semantics remain unknown. Empty `load_starts` is an observation; save loss is not established.
- Generation algorithm equivalence (RNG family/consumption, density values/Nether placeholder use, all features/carvers/structures, negative coordinates, write bounds, async order) is unverified.
- Runtime phase/tick ordering, global scheduled-tick tie behavior, unload/reload, queue limits, block/fluid hook coverage, redstone propagation and event gates are unverified. A different random tick RNG stream is a candidate requiring state/draw confirmation.
- Weather state/timers do not establish chunk precipitation or lightning implementation. Static searches are not a proof of global absence or runtime difference. `atmosphere` receives visual ownership; server effects and gameplay/entity authority need explicit handoff.
- Future test vectors may include same fixed seed/data/gamerules/time/weather/random tick speed/chunk request order, negative coordinates, biome/chunk edges, dimension min/max Y, simultaneous chunk requests, save/reload, tick ties/limits, unloaded work, random-tick speeds and neighbor/redstone chains. These are planned observations, not completed results.
- A comparison against the dedicated server (A) is not a substitute for the required integrated-server comparison (B). 100% means only all explicitly fixed and enumerated scope, never current compatibility or arbitrary datapack universality.
