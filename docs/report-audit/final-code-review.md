- **Minimal next change:** declare only the intended modules, then add the relevant entity-kind/metadata-to-model route and texture/state selection in the appropriate renderer path. Add a production-caller assertion/coverage check so an unreferenced bake cannot be counted as integrated. Do not treat compiling nonempty geometry tests as proof of rendering.

## Claims verified as wired in current source

- **Generated 26.2 shapes:** `pomme-client/src/world/block/mod.rs:174-187, 251-269, 275-288, 365-414, 474-622` loads the table only for the 26.2 native slot; validates version, total state count, block count, per-block order/name/first ID/property layout, override offset ordering/range, and shape bounds; then applies offsets derived from the block's enumerated property layout. The generator in `tools/blockgen/src/main.rs` rejects unsupported versions and verifies per-state property identity against the input. `shapes-26.2.json` parses as version `26.2`, 1,196 blocks, 32,366 states, 799 dictionary shapes and 16,980 overrides; 32,211 states were oracle-verified, 155 skipped (45 context-dependent + 110 offset-dependent), with zero oracle disagreements. The 110 offset-dependent cases and 45 context cases are explicitly not baked into state-only overrides. No assertion was found that confuses `None` with an empty shape: `physics/block_shape.rs:22-36` documents `None` as full collision, `Some(&[])` as no collision, and missing outline as full-cube fallback; callers preserve these distinctions. Context-sensitive collision remains in `physics/collision.rs` and specialized callers.
- **Registered living-model bake modules:** `renderer/mod.rs:6-11` declares the four live modules above. Current `renderer/pipelines/entity_renderer.rs::mob_definitions` contains actual calls into `entity_models::aquatic`, `::humanoid`, `::terrestrial`, and `::flying` (e.g. aquatic around 1400+, terrestrial around 1472+, humanoid around 1700+). These are compiled and routed, unlike the three modules called out above. Model bake nonempty/UV tests are present, but have not been run in this review.
- **Versioned/typed block metadata:** `world/block/mod.rs:275-346, 365-414` keys block, state-light, and optional shape data by protocol; verifies file version and state counts and checks block identity/order. Native state IDs are used directly with no remap. Only 26.2 has generated shape overrides. Unsupported launch versions visibly fall back to the native table with a warning; this is a documented state-drift limitation, not evidence of per-version shape coverage.
- **Generic translucency:** `renderer/chunk/mesher.rs:2382-2420` now rejects translucent textures from immediate edit meshes; `mesh_edit_cell` at 2446+ emits no translucent edit range. This closes the earlier disappear-until-remesh defect. `mesher.rs:3512+` routes partial-alpha faces to the translucent list; `buffer.rs:1204-1369` uploads/stores its range; `buffer.rs:1886-1927` draws visible, frustum-tested sections back-to-front; renderer frame path invokes the translucent pass (the previously reviewed `renderer/mod.rs` hook). Depth test/no depth write and alpha blend are configured for this pass. Sorting is section-center only, not per quad, and water remains a separate unsorted pass; these are known ceilings, not a newly proven failure. The trace helper now has a `translucent` branch (`mesher.rs::trace_index_start`), and the specific edit omission is addressed. No live slime capture was made.
- **Menu layouts/server authority:** Latest commit `2641c3f` (`Fix crafter menu slot layout`) corrects Crafter to 46 total slots, with its noninteractive output at slot 45 after 9 inputs + 36 player slots. `player/menu_click.rs::ContainerKind` and `ui/special_container.rs::SpecialMenu/build` agree on the 46-slot count, result index, player/hotbar indices, output position, and blocked click ops for result slot 45; crafter disabled-slot property bits/button IDs remain based on input slots 0–8. Other supported menus map storage/result indices in `SpecialMenu`. Tests assert these boundaries, but are not run and do not constitute full protocol/server integration evidence.
- **Command editor:** `interaction.rs` records a pending command-block position on the ordinary `UseItemOn` path; `app/core.rs:2919-2945` opens only for a same-position, timely block-entity response whose current block state is one of the three command block kinds and whose response has NBT. It does not infer operator rights from creative mode. `ui/command_block.rs` extracts native fields and maps sequence/auto/redstone and flag bits; `net/sender.rs::set_command_block`/encoder uses the native `set_command_block` packet ID and refuses non-native protocols, avoiding silent mis-translation. Server remains authoritative for both opening response and save validation. The old-protocol refusal is an explicit support limit. No network server was exercised.
- **Shield:** `world/block/model.rs` registers a dedicated shield geometry/texture path; held-item display selects blocking transform only while active-use and rendered/logical hand agree; interaction sync clears the pose when server using-item clears. Geometry and side selection are wired into item mesh/atlas consumers. Patterned/banner shield component rendering and actual GUI/first-person display remain unverified/unsupported as the originating notes already state.
- **Spyglass, invert-mouse, and settings:** active-use is tracked as `ActiveUseKind::Spyglass` in `player/interaction.rs`; `app/core.rs::compute_fov_modifier` consumes it and `ui/hud.rs::build_camera_overlays` receives it for the scope overlay. `renderer/camera.rs::update_look` consumes saved `invert_mouse`; options toggle calls `save_settings`. The added interaction test drives Press, a tick, Release, another tick, and server-cancel state; it asserts use/release packets and no held-button resend. This is a real `InteractionState::tick` test, not a pure packet-encoder test. It still does not exercise the renderer/FOV/HUD frame.
- **Levitation and bubble columns:** `physics/movement.rs::tick_land` applies Levitation after movement/collision resolution and before gravity/drag; bubble effects enumerate swept AABB-intersected cells in entry order, de-duplicate cells, and check the open-above rule. Added tests include full movement ticks and swept/mixed-column cases as well as pure velocity helpers. They were not run here; Steel/reference comparisons and in-game movement remain unverified.
- **Short-click and special use effects:** `interaction.rs::charge_and_latched_item_packets_follow_button_edges` sets Trident press and release before the tick sequence, then invokes the real interaction tick path and checks one use, one subsequent release, no repeat, and custom `UseEffects` speed/sprint effects.
