# Fabric Movement Observer

Independent, client-only, opt-in Minecraft 26.2 observer. It emits the schema-1 JSONL framing and typed packet payloads described below, plus selected movement observations. It is **not** a 1:1 replacement for Pomme's recorder: only the hooked values below are measured; missing fields are not synthesized from later snapshots.

## Install and record

1. Use Minecraft **26.2**, Java **25+**, Fabric Loader **0.19.5+**, and Fabric API **0.161.0+26.2**.
2. Close Minecraft normally. Back up nothing and remove/replace no existing files: copy `C:\Users\yuzum\Desktop\mine_rust\Client\diagnostic\fabric-movement-observer\build\libs\fabric-movement-observer-1.0.0.jar` into that instance's `mods` folder. For a clean observation, do not load the separate `fabric-render-probe` mod or other mods that alter rendering/gameplay.
3. Launch the Fabric client. Recording is off by default. Press **F8** to start; press **F8** again to stop. Disconnect and normal game shutdown also stop/drain the writer. The chat/status notification identifies the output path and reports writer failure or drops.
4. Files are created under `<Fabric game directory>/movement-observations/movement-<UUID>.jsonl`. Share the file only after checking its footer has `complete: true`, `dropped: 0`, and `oversize_omitted: 0`.

## Captured data and boundaries

- UTF-8 JSON Lines schema 1, `seq`, monotonic `offset_us`, `direction`, `stage`, `data`; header/footer carry start/end time, protocol 776, `client_kind: "fabric"`, queue/row/file caps, drop counts, reason, and completeness.
- A 128-row bounded non-blocking queue and single writer; the writer creates a unique file, drains on stop, writes a footer and flushes. Producers serialize only while recording is active. A bounded queue can drop records; gaps and footer counters indicate incomplete evidence.
- `LocalPlayer.tick` head/tail snapshots include `movement_tick.data.travel_observation` with the Rust common keys and vector/AABB array shapes. Values are accumulated from actual travel, jump, and move hooks; the separate `travel_observation`, `jump_observation`, and `collision_move` events are extra diagnostics. Ground drag uses the captured vanilla `computeModifiedFriction(0.91f, modifier)` return multiplied by the exact f32 friction argument, with f32 arithmetic. Step height and block speed factor are captured at their actual getter call sites. `ground_decision` records `Entity.onGround()` immediately after vanilla `Entity.move` updates it; it is the result flag, not an independent resolver reconstruction. Effective gravity is captured only when vanilla calls `getEffectiveGravity` in air, fluid, or fall-flying update; fluid adjustment gravity is the actual argument to `getFluidFallingAdjustedMovement`. `native_physics` records actual fluid moveRelative speed and vector drag coefficients where hooked (water/lava travel and fall-flying), with f32 arguments represented as their exact widened values. Those branch-only extras are not equivalents of ground friction. `frame_observation` samples `Minecraft.runTick` HEAD/TAIL monotonic duration, `LocalPlayer.tick` count, and `DeltaTracker.getGameTimeDeltaPartialTick(false)`; Minecraft does not expose Rust's simulation accumulator, so it is null with reason. All common travel keys are present on every `after_tick`; unobserved nulls receive an `unavailable_reasons` entry. No snapshot requery is substituted. Rust and Fabric still do not have identical full JSON schemas or event timing, so normalize common fields before comparison. `shape_snapshot` is a bounded, main-thread diagnostic requery at clipped moves and correction hooks: at most 32 visited block cells, 128 block AABBs, 8 entity AABBs, and 8 world-border AABBs. It reads loaded block states and collision shapes but does not mutate world state or reproduce the resolver's actual collider inputs; every query is explicitly tagged `current-world requery; NOT actual collision inputs`. Correction snapshots query at the correction hook and describe current state, not travel inputs. AABB/world state access is guarded against unloaded cells and query exceptions. `travelFlying` and true resolver context remain unavailable. Water/lava/fall-flying and gravity are call-site instrumented, but branch values are only observed when those branches actually execute in a real world; this package has no real-world movement capture yet. No GUI scale, bob, HUD, rendering, movement option, or physics state is changed.
- Connection channel observer captures an explicit movement/input/action/item-use/swing/teleport-confirm and correction/block/attribute allowlist. Packet payloads are extracted only through typed getters; no `toString`, reflection, arbitrary serialization, chat, auth, URL, or NBT fields are captured. Numeric Java floats are written as doubles (retaining the exact f32 value). The negotiated numeric wire ID is not exposed at this hook (`native_id: null`); normalized `packet` kind and typed fields are present. Native game queue/dequeue stages are not exposed and are not fabricated. `transport_write_attempt` means channel write invocation; `transport_write_success`/`transport_write_failure` use the actual Netty promise, with only the exception class emitted on failure, and do not prove server acceptance. Inbound `received` is channel-read-before-listener. Client packet listener head/tail hooks record main-thread applied states for own-player corrections, own entity velocity/teleport/attributes, block updates/sections, and block acknowledgements. Off-thread `PacketUtils` dispatch calls are skipped at listener head, so the eventual main-thread invocation is what is recorded. Block lists are capped at 4096; ack prediction internals are unavailable and emitted null. Snapshots describe observed state at the hook, not per-travel inputs or physics-used values.
- No chat, sign text, arbitrary packet, raw bytes, URL, or NBT payload is copied. Header executable identity is the current Java process executable (path/size/mtime/SHA-256); it is not mislabeled as the Minecraft artifact. `minecraft_artifact` is null because its runtime file identity was not reliably available. `source_build_revision` is embedded by the build.

## Build

From the repository root, with Java 25 selected:

```sh
fabric-render-probe/gradlew -p Client/diagnostic/fabric-movement-observer clean build
```

The separate render-probe project contributes only its Gradle wrapper and cached dependency artifacts; its mod/classes/mixins are not a dependency and are not packaged. The production jar is `build/libs/fabric-movement-observer-1.0.0.jar`. `test` is disabled; `packetFieldsSmoke` is the framework-free JavaExec fixture for typed packet getter values, packet identity/single write, EmbeddedChannel promise success/failure/void cases, bounded block-shape getters/caps, and vanilla `LivingEntity.getEffectiveGravity()` results for a controlled 0.08 gravity fixture (0.08 normally, 0.01 while descending with slow falling, 0.08 while rising). The gravity fixture calls the vanilla method itself but does not execute the movement mixin redirects or validate real-world fluid drag. The Python validator is synthetic schema/privacy coverage and rejects common travel nulls without per-field reasons; it is not a runtime or real-world data test. For a bounded development runtime smoke, run `gradlew -p Client/diagnostic/fabric-movement-observer runClient --offline -PobserverSmoke` with Java 25. The Gradle property explicitly passes `-Dmovementobserver.classloadSmoke=true` and `-Dmovementobserver.smokeAutoStop=true` to the Minecraft child JVM; normal `runClient` is unchanged. Verify all six `classloadSmoke PASS` lines, successful required Mixin transforms, the lifecycle auto-stop, and process exit code 0 in that run's actual output. No game server is joined, no user game window is touched, and no account is needed for fixtures. This smoke does not validate F8/save-path recording or physics values from an actual world; compare those only in a controlled local world/server with matching position and input.
