# Fabric Movement Observer

Independent, client-only, opt-in Minecraft 26.2 observer. It emits the schema-1 JSONL framing and typed packet payloads described below, plus selected movement observations. It is **not** a 1:1 replacement for Pomme's recorder: only the hooked values below are measured; missing fields are not synthesized from later snapshots.

## Install and record

1. Use Minecraft **26.2**, Java **25+**, Fabric Loader **0.19.5+**, and Fabric API **0.161.0+26.2**.
2. Close Minecraft normally. Back up nothing and remove/replace no existing files: copy `C:\Users\yuzum\Desktop\mine_rust\Client\diagnostic\fabric-movement-observer\build\libs\fabric-movement-observer-1.0.0.jar` into that instance's `mods` folder. For a clean observation, do not load the separate `fabric-render-probe` mod or other mods that alter rendering/gameplay.
3. Launch the Fabric client. Recording is off by default. Press **F8** to start; press **F8** again to stop. Disconnect and normal game shutdown also stop/drain the writer. The chat/status notification identifies the output path and reports writer failure or drops.
4. Files are created under `<Fabric game directory>/movement-observations/movement-<UUID>.jsonl`. Share the file only after checking its footer has `complete: true`, `dropped: 0`, and `oversize_omitted: 0`.

## Captured data and boundaries

- UTF-8 JSON Lines schema 1, `seq`, monotonic `offset_us`, `direction`, `stage`, `data`; header/footer carry start/end time, protocol 776, `client_kind: "fabric"`, queue/row/file caps, drop counts, reason, and completeness.
- A 128-row bounded non-blocking queue and single writer; writer drains on stop and flushes a footer. Rows are capped at 12 MiB and each file at 1 GiB. Raw packet frames are capped at 8 MiB each; all caps/queue drops make the footer incomplete. The queue's theoretical string-memory ceiling is high (128 × 12 MiB); typical packet rows are far smaller.
- `LocalPlayer.tick` head/tail snapshots include `movement_tick.data.travel_observation` with the Rust common keys and vector/AABB array shapes. Values are accumulated from actual travel, jump, and move hooks; the separate `travel_observation`, `jump_observation`, and `collision_move` events are extra diagnostics. Ground drag uses the captured vanilla `computeModifiedFriction(0.91f, modifier)` return multiplied by the exact f32 friction argument, with f32 arithmetic. Step height and block speed factor are captured at their actual getter call sites. `ground_decision` records `Entity.onGround()` immediately after vanilla `Entity.move` updates it; it is the result flag, not an independent resolver reconstruction. Effective gravity is captured only when vanilla calls `getEffectiveGravity` in air, fluid, or fall-flying update; fluid adjustment gravity is the actual argument to `getFluidFallingAdjustedMovement`. `native_physics` records actual fluid moveRelative speed and vector drag coefficients where hooked (water/lava travel and fall-flying), with f32 arguments represented as their exact widened values. Those branch-only extras are not equivalents of ground friction. `frame_observation` samples `Minecraft.runTick` HEAD/TAIL monotonic duration, `LocalPlayer.tick` count, and `DeltaTracker.getGameTimeDeltaPartialTick(false)`; Minecraft does not expose Rust's simulation accumulator, so it is null with reason. All common travel keys are present on every `after_tick`; unobserved nulls receive an `unavailable_reasons` entry. No snapshot requery is substituted. Rust and Fabric still do not have identical full JSON schemas or event timing, so normalize common fields before comparison. `shape_snapshot` is a bounded, main-thread diagnostic requery at clipped moves and correction hooks: at most 32 visited block cells, 128 block AABBs, 8 entity AABBs, and 8 world-border AABBs. It reads loaded block states and collision shapes but does not mutate world state or reproduce the resolver's actual collider inputs; every query is explicitly tagged `current-world requery; NOT actual collision inputs`. Correction snapshots query at the correction hook and describe current state, not travel inputs. AABB/world state access is guarded against unloaded cells and query exceptions. LivingEntity's separate `travelFlying` branch and true resolver context remain unavailable; this does not apply to the own-player creative-flight path, which is `Player.travel` calling normal `super.travel` and then applying vertical drag. `native_physics.move_relative_speed_f32` and `move_relative_input_vec3` are observed at the actual bytecode invocation `LivingEntity.moveRelative(F, Vec3)` (declared in `Entity`) inside `LivingEntity.handleRelativeFrictionAndCalculateMovement`, distinguishing used acceleration inputs from a speed getter snapshot. `creative_vertical_drag_f64` records the unchanged `0.6` constant at the own-player `Player.travel` call site (not a replacement movement rule). These values are branch-only and require active recording in an actual world to collect. No GUI scale, bob, HUD, rendering, movement option, or physics state is changed.
- `PacketEncoder`/`PacketDecoder` hooks capture the actual unmodified plaintext packet bytes at the codec boundary (after inbound decompression and before outbound compression/encryption), including the original VarInt packet ID and payload. Raw rows cover PLAY and CONFIGURATION only; HANDSHAKING, STATUS and LOGIN are intentionally excluded. This includes server-owned cookie/custom-payload/chat/NBT bytes in those allowed phases. The capture performs no packet reserialization, getter dump, reflection or `toString`; bytes are base64 under `payload_base64`, `payload_layout: id_plus_payload`, and the phase is explicit. Raw packet content may contain server-provided authentication/cookie material; treat every log as private and do not publish it. No game-window/world manipulation is performed. `packet_type` is the public packet identifier when available; typed events retain explicit getter allowlists with an `unknown_typed` fallback and no class dumps. Legacy `native_id` remains null there; the actual numeric ID is in corresponding raw bytes. Native queue/dequeue stages are not fabricated. `transport_write_attempt` means channel write invocation; success/failure is the actual Netty promise and does not prove server acceptance. Existing client packet listener hooks capture applied states and do not substitute for raw packet bytes.
- Keyboard and mouse hooks observe game-window key/button press, release and repeat actions, modifier/scancode integers, scroll and cursor callbacks, with a small fixed label map. Only callbacks for Minecraft's own window are observed. Character/IME text events are not hooked; input outside the game window is not captured.
- Raw packet bytes are deliberately included by explicit user authorization above; this means packet-contained chat/cookie/NBT data is not redacted. Do not share logs publicly. No OS-global keystrokes, character/IME text, window titles, URLs or unrelated process files are captured. Header executable identity is the current Java process executable (path/size/mtime/SHA-256); it is not mislabeled as the Minecraft artifact. `minecraft_artifact` is null because its runtime file identity was not reliably available. `source_build_revision` is embedded by the build.

## Build

From the repository root, with Java 25 selected:

```sh
fabric-render-probe/gradlew -p Client/diagnostic/fabric-movement-observer clean build
```

The separate render-probe project contributes only its Gradle wrapper and cached dependency artifacts; its mod/classes/mixins are not a dependency and are not packaged. The production jar is `build/libs/fabric-movement-observer-1.0.0.jar`. `test` is disabled; `packetFieldsSmoke` is the framework-free JavaExec fixture for typed packet getter values, packet identity/single write, EmbeddedChannel promise success/failure/void cases, bounded block-shape getters/caps, and vanilla `LivingEntity.getEffectiveGravity()` results for a controlled 0.08 gravity fixture (0.08 normally, 0.01 while descending with slow falling, 0.08 while rising). The gravity fixture calls the vanilla method itself but does not execute the movement mixin redirects or validate real-world fluid drag. The Python validator is synthetic schema/privacy coverage and rejects common travel nulls without per-field reasons; it is not a runtime or real-world data test. For a bounded development runtime smoke, run `gradlew -p Client/diagnostic/fabric-movement-observer runClient --offline -PobserverSmoke` with Java 25. The Gradle property explicitly passes `-Dmovementobserver.classloadSmoke=true` and `-Dmovementobserver.smokeAutoStop=true` to the Minecraft child JVM; normal `runClient` is unchanged. Verify the expected classload smoke lines (including `PacketEncoder`, `PacketDecoder`, `KeyboardHandler`, and `MouseHandler`), successful required Mixin transforms, the lifecycle auto-stop, and process exit code 0 in that run's actual output. No game server is joined, no user game window is touched, and no account is needed for fixtures. This smoke does not validate F8/save-path recording or physics values from an actual world; compare those only in a controlled local world/server with matching position and input.
